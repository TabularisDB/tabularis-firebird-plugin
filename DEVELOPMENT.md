# Driver completion (0.2.0-beta.3)

The published v0.1.0 tag and registry-signed assets remain unchanged in the original repository. Development and releases continue on `main` in [TabularisDB/tabularis-firebird-plugin](https://github.com/TabularisDB/tabularis-firebird-plugin). This checklist tracks current main and remaining work before stable release. The earlier v0.2.0-beta.1 release and its assets remain unchanged.

The companion host implementation for PSQL splitting, task cancellation and transaction-state refresh is tracked in [TabularisDB/tabularis#1462](https://github.com/TabularisDB/tabularis/pull/1462). It is a draft pending upstream checks and review; creating it does not make the functionality available in a released host.

- [x] Host `cancel` notifications interrupt the matching request, including a stalled authentication handshake. No notification response is emitted; queued requests remain usable.
- [x] Honor `connect_timeout_secs` (default 10) and `query_timeout_secs` (default 0, unlimited). Zero disables the corresponding deadline.
- [ ] Enable the host's dedicated query-timeout connection field once the deployed registry schema permits `capabilities.query_timeout`. For now the plugin setting `query_timeout_secs` supplies the default; an explicit host connection value overrides it, including zero. The current registry rejects that capability flag, so it is deliberately omitted from the static manifest.
- [x] Abort only the cancelled request's dedicated attachment. Live Firebird 3/4/5 tests verify the attachment disappears from MON$ATTACHMENTS after cancellation/timeout.
- [x] Configurable buffer limits: 100,000 retained rows, 64 MiB of row/header JSON, and 8 MiB per decoded BLOB by default. Limits reject the result instead of returning partial data. BLOB results fetch one row per batch to bound prefetching.
- [x] Parameterized INSERT/UPDATE/DELETE, complete-PK validation, affected counts, exact decimal parameters, RETURNING, automatic rollback on errors and row-count violations.
- [x] Atomic query batches with combined result limits; no implicit retry after an unknown commit outcome.
- [x] Pinned interactive transactions across requests with `session_id`; BEGIN/START TRANSACTION/SET TRANSACTION, read-only/read-write modes, snapshot/read-committed isolation, savepoints and retaining commit/rollback. Release, process EOF, execution errors, cancellation and deadlines roll back an open transaction. At most 32 sessions retain an attachment; connection changes are rejected while its transaction is open.
- [x] SQL builders for tables, columns, indexes and composite foreign keys; column comments and view create/alter/drop. Primary-key/identity status changes currently require explicit SQL.
- [x] Firebird type catalog, with additional Firebird 4+ types discovered per connection.
- [x] Public package routines and legacy UDF parameter metadata, with reversible quoted identities and routine-type discriminators for procedure/function name collisions. Private members remain excluded. Package source falls back to its body when individual source is unavailable; external source reports an explicit error.
- [x] Table, database and DDL trigger discovery, full PSQL create/edit scripts and create/alter/drop RPCs; preserve active status, position and event order. Unknown event codes remain explicit and cannot be regenerated as guessed SQL.
- [x] Read-only sequence catalog RPC (`get_sequences`) exposes initial value, increment and comment without consuming sequence values. The host currently has no sequence-explorer contract.
- [x] Firebird routine-call SQL builder: match arguments by catalog name/order, escape literals, and distinguish selectable procedures, executable procedures and scalar functions, including package members.
- [x] Routine creation-template, edit-script and drop RPCs. PSQL edit scripts read one catalog snapshot and preserve domains, TYPE OF / TYPE OF COLUMN, defaults, NOT NULL, character sets, collations, deterministic status and Firebird 4+ SQL SECURITY. They use ALTER for top-level routines, preserving grants and parameter comments. Package edits return the complete RECREATE PACKAGE BODY script; legacy UDF edits alter entry-point/module bindings. Dropping a package member is rejected without touching its package; external UDR edit scripts remain engine-specific and are explicitly rejected.
- [ ] Complete routine-management UI support and native editor validation. A host patch adds opt-in `sql_syntax.psql_blocks` splitting for Firebird declarations, nested bodies, local routines, packages, alternative quoted strings and isql SET TERM directives. Its real editor splitter has been exercised against this plugin on Firebird 3/4/5. `routine_management` and `psql_blocks` remain absent from the plugin manifest until a compatible host and registry schema are deployed and the native editor is validated. All four routine-management RPCs are available directly. The manifest explicitly extends generic syntax rather than inheriting PostgreSQL rules or advertising another engine's dialect.
- [x] Prepare-only detailed execution plans, rendered as a host-compatible tree with the original text retained. Tested on Firebird 3/4/5, including DML with no side effects. Runtime analysis is explicitly rejected; unavailable costs and row estimates remain null.
- [ ] Runtime analysis, column statistics, BLOB export/preview and lossless SQL export/import.
- [x] ChaCha64/ChaCha wire encryption through RustCrypto, with Arc4 compatibility for Firebird 3. Protocol 16 carries modern cipher IVs and execution timeout trailers; Firebird 3 uses protocol 13. Encryption is required by default; `wire_crypt` and `allow_arc4` settings or connection `extra` overrides define explicit policy. Malformed offers and unavailable allowed ciphers fail closed. Cipher writes handle short/interrupted TCP writes and poison the stream after a partial I/O failure. Unit tests cross the 32-bit ChaCha counter boundary; live tests force each cipher and a plaintext server. Protocols 10–12 and legacy password authentication are no longer advertised or implemented; this plugin targets Firebird 3+ with SRP.
- [x] Role and character-set settings plus per-connection `extra` overrides. Include effective role/charset in session identity; reject changes while a transaction is open. UTF-8 DPB strings preserve quoted/non-ASCII roles independently of the connection charset. Decode SQLDA names strictly instead of silently returning empty aliases. Text BLOB descriptors and long bound text retain their character sets; explicit BLOB filter parameters convert text to UTF-8 JSON without changing binary data. Live Firebird 3/4/5 coverage includes UTF8/WIN1252/ISO8859_1, short/empty/multi-segment text, Unicode, mixed storage charsets, binary bytes and explicit encoding failures with recovery. Firebird still applies the connection charset, so ASCII cannot retrieve Japanese text; NONE/OCTETS are not text encodings. Other supported legacy codecs are selectable but have not each had a language-specific live roundtrip. Embedded mode remains outside this network driver's scope.
- [x] Restricted-user role test: an unprivileged user cannot SELECT without its role, can SELECT with its granted quoted Unicode role, and still cannot DELETE. The test user, role and table are removed; the isolated server/security database is deleted afterwards.
- [x] Bounded workload and failure-injection regression tests: reject 100,001 buffered rows while allowing a ten-row page with the exact total; reject an over-8-MiB text BLOB and recover; roll back a batch whose combined results exceed 100,000 rows; run eight concurrent writers with 160 independent inserts while conflicting updates fail against a held row lock. No partial failed-batch writes remain. These are fixed-size correctness workloads, not a measured RSS or throughput guarantee.
- [x] Simulate the loss of a COMMIT reply through a transparent TCP relay, independently verify that the commit already reached the database, and require unknown-outcome reporting with no replay. Terminate an attachment from the server, verify pending writes roll back, and verify a fresh session can proceed.
- [x] Stdio overload test fills the 32-request queue, rejects 33 excess requests and a duplicate ID, cancels both a running and a queued request, drains the queue and reuses the completed ID without stale request controls.
- [x] Native Linux x64 live-test jobs for Firebird 3/4/5 using official Docker images pinned by architecture-specific digest. The same catalog, type, workload, failure-injection and session/stdio suites run as on Windows. Containers, anonymous volumes, newly pulled images and temporary credentials are cleaned up. No Docker or Firebird installation is added to the Windows development PC.
- [x] Optional `get_session_state` RPC returns the actual retained transaction state without creating an attachment or issuing SQL. Missing sessions report false; malformed or missing session IDs are rejected. Live tests cover open transactions and state after a timeout. A companion host patch refreshes this state after failed/cancelled calls and sends cancellation when an awaiting task is aborted, including under command-queue pressure.

Cancellation uses Firebird's documented `fb_cancel_abort` behavior (socket shutdown). Because Windows shutdown does not reliably wake a blocked receive, the wire stream also checks an attachment cancellation signal between 100-ms receive waits. Ordinary receive timeouts retry while the request is active, preserving unlimited query behavior. The signal follows the attachment through session rebinds and is detached from completed request controls, so a late cancellation cannot poison an idle session. Writes keep their existing socket-shutdown behavior; a failed write is never retried by this receive fallback. Cancellation aborts the active request's attachment and rolls back its open transaction, including a pinned session. It does not preserve an aborted connection. TCP connect waits until the configured connect deadline or OS result; a blocked OS DNS resolver can finish in the background after the caller has stopped waiting. The deadline begins before DNS and authentication. Results are still fully scanned for their exact count; set a query deadline or use SQL row limits for costly queries.

This is a bounded-memory policy for decoded BLOBs and retained results, not a strict process-RSS limit. JSON serialization, wire buffers and the current row add transient allocations. These defaults apply to metadata as well as query results and can be changed in plugin settings. Long-running metadata statements honor the same request cancellation and query deadline.

The development manifest enables writes. Metadata still uses read-only transactions. By default, transactions use READ COMMITTED RECORD_VERSION and NO WAIT, so ordinary reads see committed versions while another editor has pending changes. A single autocommit statement commits once after successful execution/fetch; a failed statement, result-limit violation or grid mutation affecting more than one row rolls back. `execute_query_batch` without explicit transaction control executes up to 1000 statements in one transaction and rolls back the entire batch on error. Its timeout covers the full batch, including commit; Firebird may reject DDL/DML combinations that require a metadata commit between statements. A commit whose reply is lost reports an unknown outcome and must not be automatically retried. Counters such as identity generators are not rolled back by Firebird.

With `session_id`, query responses carry `{result, in_transaction}` and batch responses `{results, in_transaction}`. Query failures carry `{error, error_code, in_transaction}` inside the RPC result so the host updates its transaction indicator; batch failures carry error entries and the resulting transaction state. Any execution/control error discards the attachment and rolls back all still-pending changes. A changed connection is rejected while preserving the original transaction. A batch with explicit transaction boundaries follows those boundaries: prior explicit commits or autocommit statements cannot be rolled back by a later error. `release_session` is idempotent and rolls back pending changes. Open transactions have no silent idle expiry; closing the editor/process releases them. Cleanup has a five-second socket-abort deadline. Transaction commands require a session and support the documented subset above; unsupported clauses are rejected instead of ignored. Native editor UX still needs validation before release.

If an older host discards a cancelled call's response before reading its state, its cached transaction indicator can remain stale until the next session request. The aborted transaction is still gone; a subsequent COMMIT is rejected rather than replayed on a new connection. The companion host patch calls `get_session_state` with `{session_id}` and consumes `{in_transaction}` with a five-second deadline. Unsupported, unavailable or malformed probes retain the last reported state instead of inventing a closed transaction. A queued cancellation may preserve an existing transaction, so the host must query the plugin rather than unconditionally clear its indicator. Deployment of that host patch and native cancellation UX remain release-validation items.
