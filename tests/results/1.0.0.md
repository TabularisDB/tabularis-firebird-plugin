# 1.0.0 validation

Release source: `19de3268ba78771cc68a7cd7829f8e76ca55da22`, tag `v1.0.0`.
The existing [release CI](https://github.com/TabularisDB/tabularis-firebird-plugin/actions/runs/42932036516)
validates and packages this exact tag before automatic publication. It is the
only newly started platform pipeline for this release; no additional long soak
or manual five-platform desktop run was requested. This report's later updates
are documentation only and do not change the tagged runtime or assets.

The stable release adds native transportable Firebird backups over the encrypted
Services API. There is no runtime dependency on a local Firebird client or gbak.

## Local checks

- Workspace unit tests: 44 plugin tests, four stdio/protocol tests and 57 vendored
  driver tests passed. Native backup handshake cancellation and timeout preserve
  an existing output file and leave subsequent stdio requests usable.
- Strict plugin Clippy and formatting passed. The vendor is tested as a workspace
  member; its preexisting broad Clippy warnings are not presented as a clean
  strict vendor audit.
- Live native roundtrips passed on Firebird 3/4/5 during development. Windows
  fixtures populate a two-dimensional INTEGER array through the native API
  (test-only), then compare all six restored values including both integer
  extremes. Fixtures also check mixed object ownership, routines, a non-text
  BLOB larger than 8 MiB, existing-target protection and failed-export retention.
- Full Firebird 3/4/5 regressions passed after adding user-defined BLOB subtype
  support to the SQL roundtrip (20 live plugin tests on 3, 21 on 4/5, plus stdio).
  Native cases additionally verify external-table conversion and suppression of
  a connection trigger that otherwise rejects connections. A Dialect-1 native
  roundtrip and independent gbak restore passed on Firebird 3 and 5.
- Explicit plaintext policy passed the new Services SRP-proof handshake as well
  as the default encrypted 3/4/5 cases. Full source/platform CI runs before release.
- Host typechecking/build, 22 focused React tests, 19 backend transfer tests and
  lint for the changed production TypeScript passed. Test files are excluded by
  the Host ESLint configuration and are validated through Vitest/typechecking.
- A fresh isolated Windows Tauri/WebView run passed all eight groups: editor
  CREATE/INSERT, trigger create/edit/failure recovery, SQL export/restore,
  native-format selection/export, FBK restoration detected independently of
  the filename extension and existing-target protection. File pickers use the existing
  owned-path mock; OS secrets were denied. The private profile/server were removed.
  This build contained the native-backup changes based on Host d13cc8fa; the final
  capability-gated sidebar filter is covered by typechecking and the pinned CI run.
- The registry capability patch helper passed a local preservation/idempotence
  test. Applying it was explicitly deferred; no operator credentials were used.

## Scope and integration

Native restore is create-only. It can leave a partial new database after an
engine error, cancellation or lost reply; the error reports this and no unknown
target is automatically deleted. Source shadow files are omitted. External-table
data becomes ordinary tables. Server accounts, configuration, encryption keys
and external modules remain separate dependencies.

Array grid values still require a dedicated array-editing protocol; the native
backup covers their preservation. SQL-only transfers retain the representation
limits documented in README. No unrestricted SQL-only reconstruction is claimed.

Host PR #1470 provides native-format UI selection and still requires upstream
merge/release. Registry schema changes are deferred and the related static flags
remain gated. Earlier five-platform desktop, macOS compatibility and two-hour
core-soak evidence is in beta7.md; that soak did not exercise the new native
backup protocol and is not described as native-backup soak coverage.

The companion Host implementation is committed as
`a2c38c3f47e0e1686232d0058bf59868d7cf5cb2`; future five-platform desktop runs pin
that exact revision. The successful local eight-group run is retained in
`1.0.0-windows-native.json`, with its candidate-build provenance stated explicitly.
